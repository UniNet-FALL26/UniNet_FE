## Semantics
This page manages registered availability, not confirmed appointments. No invented availability status or booked/free badge. Multi-day slots show original dates/times so editing and deleting the entire registered interval is explicit.

Editor validation now reports each cause separately. An end time earlier than or equal to start reports **Giờ kết thúc phải sau giờ bắt đầu.**, before other interval checks. Missing/invalid times, past start, duration over 31 days and the 365-day horizon each have their own message. Changing a time clears the previous error. Browser fixture verifies both earlier and equal end times are rejected without a POST, followed by a successful corrected save.

## Calendar HTTP 400 fix
The backend `VerificatorAvailabilityService.ListAsync` rejects ranges longer than 31 days (`INVALID_AVAILABILITY_RANGE`); the calendar originally requested all 42 visible days in one request. `loadCalendarAvailability` now splits the visible range into contiguous requests of at most 31 elapsed days, passes the same abort signal, deduplicates crossing intervals by ID and sorts the combined result. A failed chunk rejects the entire load so partial data is not displayed as complete. No backend changes or deployment required for the fix.

The browser fixture now enforces the actual backend 31-day limit (previously missing), and passes calendar navigation/CRUD at five widths with that validation enabled.
